# ORIVANA — working rules

Frontend prototype of ORIVANA ("Personal Intelligence & Action Platform"). No backend yet; a typed mock layer stands in for the Go API.

## Stack

`apps/web`: React 19 + TypeScript + Vite + Tailwind CSS v4 + shadcn-style components on Radix (`radix-ui`) + React Router 7 + TanStack Query + React Flow (`@xyflow/react`). Shared contract: `packages/contracts` (types + fixtures).

```
npm install          # root (npm workspaces)
npm run dev          # http://localhost:5173
npm run build        # tsc --noEmit + vite build
npm test             # vitest (service lifecycle tests)
node packages/contracts/scripts/generate-fixtures.mjs   # regenerate fixtures
```

## Data rules (mandatory)

- No hard-coded content in components. Papers, messages, citations, entities, memories, proposals, events — everything dynamic — comes from JSON fixtures.
- `packages/contracts/types/` = one file per entity (PRD §10). `packages/contracts/fixtures/` = JSON per endpoint (PRD §14), generated by `scripts/generate-fixtures.mjs`; edit the generator, not the JSON.
- `apps/web/src/services/` = mock REST functions (`listSources`, `sendMessage`, `openMessageStream`, `approveProposal`, …) with simulated latency, errors (`{ code, message, details, request_id }`), and an in-memory store seeded from fixtures.
- Only `services/core/fixtures.ts` imports JSON. Components call hooks; hooks call services. Components never import JSON or services' store.
- Assistant streaming is simulated SSE with events `status`, `token`, `citation`, `done`, `error`.
- `docs/API-CONTRACT.md` is what the Go backend implements; keep it in sync with types and services.

## UI rules (mandatory)

- UI text in English. Tagline and category exactly as in PRD. Never call the product "autonomous".
- No raw hex in components — use tokens (`bg-surface`, `text-fg-muted`, `border-control`, `text-knowledge`, …) defined in `src/styles/index.css`.
- Primary buttons: `on-accent` text (#0B0D12) on `accent` (#8B9CFF). Never white on the accent.
- Statuses (Candidate, Confirmed, Superseded, Rejected, Failed, …) always have text or an icon, never colour alone — use `StatusBadge` / `OriginBadge`.
- Actions are `<button>`; navigation is `<a>` / `Link` (`ButtonLink` for button-styled links).
- Every interactive element is keyboard reachable with the visible focus ring (2 px accent, 2 px offset).
- Components ≈ 200 lines max; split larger ones.
- Never show success before the mock service confirms it (no optimistic "Succeeded"; approvals show Executing until `verified_at`).
- Screens with ≥ 3 internal columns (Assistant, Graph, Document viewer) collapse the app sidebar to the 64 px rail.
- Loading, empty, and error states for every async view (`LoadingSkeleton`, `EmptyState`, `ErrorState`).
