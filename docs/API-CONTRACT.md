# ORIVANA — API contract (v1)

This document is the contract between the React prototype (`apps/web`) and the Go backend. The prototype's mock services (`apps/web/src/services`) implement exactly these shapes. The Go API must match them field for field.

- **Types:** `packages/contracts/types/*.ts` (one file per entity, following PRD §10).
- **Examples:** `packages/contracts/fixtures/**.json`. They are generated by `node packages/contracts/scripts/generate-fixtures.mjs`. Edit the generator, not the JSON.
- **Source of truth:** PRD §9.5 (SSE), §10 (data model), §14 (endpoints). Endpoints marked **extension** are not in PRD §14. The screens need them; see `docs/design/SCREENS.md` §3 #12.

---

## 1. Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1` |
| Auth | Server-side session in an `HttpOnly; Secure; SameSite=Lax` cookie. No bearer tokens in the browser. |
| CSRF | Every non-GET request sends `X-CSRF-Token` (value from the `orivana_csrf` cookie). |
| Content type | `application/json; charset=utf-8`, except SSE (`text/event-stream`) and CSV export (`text/csv`). |
| Timestamps | ISO 8601 in UTC, e.g. `"2026-11-11T07:20:00Z"`. The client formats them in `user.time_zone`. |
| IDs | Opaque strings with a type prefix (`src_`, `prj_`, `conv_`, `msg_`, `ent_`, `rel_`, `mem_`, `dec_`, `prop_`, `run_`, `evt_`, `job_`, `conn_`). |
| Pagination | Cursor based: `?cursor=…&limit=…` → `{ "items": [], "next_cursor": "…" \| null, "total": 46 }`. Default `limit` is 8 for sources and 10 for audit events. |
| Request IDs | Every response carries an `X-Request-Id` header. Errors repeat it in `request_id`. |
| Idempotency | Every write that creates something accepts `Idempotency-Key`. Action proposals use their own `idempotency_key` when they execute. |
| Tenant scope | Every endpoint checks workspace membership. A resource outside the caller's workspace returns `404`, never `403`, so that existence does not leak. |
| Writes to external apps | Only `POST /action-proposals/{id}/approve` can cause an external write. Nothing else may call a connector's write capability. |

## 2. Error format

```json
{
  "error": {
    "code": "INVALID_CREDENTIALS",
    "message": "Email or password is incorrect.",
    "details": { "field": "password", "attempts_left": 3, "lockout_minutes": 10 },
    "request_id": "req_8a20d4e1"
  }
}
```

`message` is safe to show to the user. `details` is optional and machine-readable (`field` names the form field to mark).

## 3. Error codes

| Code | HTTP | When | UI behaviour |
|---|---|---|---|
| `VALIDATION_FAILED` | 422 | Bad input, or a proposal that is not validated | Inline field errors from `details.field` |
| `UNAUTHENTICATED` | 401 | No session, or the session expired | Redirect to `/sign-in?expired=1` |
| `INVALID_CREDENTIALS` | 401 | Wrong email or password | Alert + `details.attempts_left` |
| `EMAIL_NOT_VERIFIED` | 403 | Sign-in or upload before verification | Verify-email alert with resend |
| `TOKEN_EXPIRED` / `TOKEN_USED` | 410 | Verification or reset link is no longer valid | "This link has expired" card |
| `RATE_LIMITED` | 429 | Too many attempts (`details.retry_after_seconds`) | Countdown, disabled submit |
| `FORBIDDEN` | 403 | Role not allowed | Error state |
| `NOT_FOUND` | 404 | Unknown id or another workspace's id | Not-found state |
| `CONFLICT` | 409 | Stale `revision`, duplicate email, already decided | Reload prompt |
| `SOURCE_PROCESSING` | 409 | The cited source is still being parsed or indexed | "Source still processing" state |
| `PDF_ENCRYPTED` | — | Job error code (not an HTTP error) | Failed badge + retry hint |
| `MODEL_TIMEOUT` | — | SSE `error` event | "Answer failed" + Retry answer |
| `CONNECTION_NEEDS_RECONNECT` | 409 | The connector token was rejected | "Needs reconnect" card |
| `INTERNAL` | 500 | Anything unexpected | Generic error state with request id |

## 5. Streaming (SSE)

Flow (PRD §9.5):

1. `POST /conversations/{id}/messages` stores the user message and returns `{ "user_message": {…}, "message_id": "msg_…" }`.
2. The client opens `new EventSource('/api/v1/conversations/{id}/messages/{message_id}/stream')`. Cookies are sent automatically.
3. The server emits the events below and closes the stream after `done` or `error`.
4. The stream may be reopened (EventSource reconnect, or a remounted client) until it finishes; the server replays it from the start or resumes with `Last-Event-ID`.
5. `POST …/cancel` stops generation. The server then emits `done` with `message.status = "cancelled"` and the partial content (`cancelled_at` set).

Wire format:

```text
event: status
data: {"phase":"retrieving","steps":[{"label":"Scope resolved — Project RAG Comparison · 14 sources","state":"done"},{"label":"Searching keyword + vector index, expanding 1 graph hop","state":"active"},{"label":"Generating answer from the evidence packet","state":"pending"}],"passages_found":12,"sources_found":5,"sources":[{"label":"Okafor et al. 2025","passages":4}]}

event: token
data: {"text":"Two sources report that hybrid "}

event: citation
data: {"id":"cit_…","ordinal":1,"chunk_id":"chk_santos_0401","source_id":"src_santos2025","source_title":"Fusion Retrieval Revisited: BM25 + Dense on Open-Domain QA","source_label":"Santos & Lee 2025","source_meta":"Santos & Lee, 2025","page":4,"section":"3.1 Main results","passage":"…","quote":"…","char_start":58,"char_end":129}

event: done
data: {"message":{ …complete Message, status "complete" }}

event: error
data: {"code":"MODEL_TIMEOUT","message":"The model didn’t respond in time","details":{"passages_retrieved":12,"memory_written":false},"request_id":"req_7d2e9f10","retryable":true}
```

| Event | Payload type | Notes |
|---|---|---|
| `status` | `StatusEventData` | `phase` is `retrieving` or `generating`. Sent whenever the counts or steps change. |
| `token` | `{ text }` | Append to the answer in order. |
| `citation` | `MessageCitation` | Sent once per citation, after the tokens that reference it. |
| `done` | `{ message: Message }` | Authoritative final message; replaces the streamed draft. |
| `error` | `ApiError & { retryable }` | Ends the stream. `retryable: true` allows "Retry answer" (re-runs generation only). |

Recorded streams for every Assistant state are in `fixtures/streams/`. Each is `{ message_id, events: [{ event, data, delay_ms }] }`:

| Fixture | State |
|---|---|
| `answer.hybrid.sse.json` | Retrieving → generating → answer with 3 citations |
| `no-evidence.sse.json` | Abstains; one "closest passage" citation |
| `conflicting.sse.json` | Two positions plus a labelled inference |
| `proposal.create-issue.sse.json` | Answer that links an action proposal (`proposal_id`) |
| `error.model-timeout.sse.json` | `error` after retrieval finished |

## 6. Mock behaviour in the prototype

The mock layer (`apps/web/src/services`) follows this contract and adds:

- 250–700 ms latency per request, with `request_id`s in errors.
- An in-memory store seeded from the fixtures. Writes (confirm, reject, approve, edit, delete) change the store for the rest of the browser session. Reloading the page resets it.
- Execution after approval: `executing` (about 2 s) → `verifying` (about 1.5 s) → `succeeded` with verification checks.
- Stream scenario selection by the question text: "learning rate" → no evidence, "chunk size" → conflicting, "issue" → proposal, "simulate error" → model timeout, anything else about retrieval → the hybrid answer. Unrelated questions abstain.
